test(outbox): native multi-backend concurrency regression

Closes the native-PostgreSQL concurrency gap left open by the release
candidate evidence: PGlite's single WASM backend could never exercise
several real backends at once, and every existing database-gated test
pinned max_connections(1) over per-connection TEMP tables.

One bounded store-level regression on the real migrated workflow_outbox
(rows keyed under a unique run prefix, deleted before any assertion can
fail the test):

- eight backends race the same (outbox_kind, event_key) queue insert:
  exactly one row survives the dedupe
- two backends mark the same row failed concurrently: attempt_count
  lands exactly at 2 and the row stays pending (no silent loss)
- four reconciler readers poll concurrently: wake readers see only
  OWNER_ASSISTANCE_WAKE, kick readers only EXECUTION_KICK, FORUM_EVENT
  rows stay untouched (optional Forum isolation under concurrency)

Requires TEST_DATABASE_URL naming an isolated PostgreSQL instance with
the migrations applied (applied on first use when missing); same
contract as the existing database-gated cases. Test-only delta; no
behavior change, no migration.
